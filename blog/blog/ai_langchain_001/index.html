变革

《Attention Is All You Need》是人工智能领域，特别是自然语言处理（NLP）的里程碑式论文，它提出了完全基于注意力机制的 Transformer 模型架构，彻底改变了序列建模的范式，并成为当今所有大语言模型（如GPT、BERT等）的核心基础。

一、论文简介​

  • 发表时间：2017年6月，由谷歌的研究团队发布。
  • 核心思想：摒弃了之前主流的循环神经网络（RNN）和卷积神经网络（CNN），仅使用“注意力机制”（特别是“自注意力机制”）来构建一个编码器-解码器架构，用于机器翻译任务。
  • 关键创新：
    1. 自注意力机制：让序列中的每个词都能直接与序列中所有其他词建立联系，计算它们之间的相关性权重，从而更好地捕捉长距离依赖和上下文信息。
    2. 多头注意力：将注意力机制并行化多份，让模型可以同时关注来自不同“表示子空间”的信息。
    3. 位置编码：由于模型本身没有循环或卷积结构来感知顺序，因此引入了正弦/余弦位置编码，为输入序列中的词注入位置信息。
    4. 并行化训练：Transformer模型结构完全并行，训练速度远快于必须顺序处理的RNN。

二、历史地位与影响​

这篇论文的历史地位可以概括为 “开创了AI新时代的基础架构”。

  1. 范式革命：它证明了在序列建模任务中，注意力机制可以完全取代RNN和CNN，并且效果更好、训练更快。这直接导致了RNN在NLP主流研究中迅速被边缘化。
  2. 大语言模型的基石：后续所有划时代的预训练语言模型都基于Transformer架构构建：
    • GPT系列：使用了Transformer的解码器部分，专注于生成任务。
    • BERT系列：使用了Transformer的编码器部分，专注于理解任务。
  3. 跨领域扩展：其影响力远超NLP，已广泛应用于计算机视觉（ViT）、语音识别、蛋白质结构预测（AlphaFold2）等多个领域。
  4. 开启AI新浪潮：Transformer的可扩展性（模型可以做得非常大）和高效并行能力，直接催生了“预训练+微调”的范式，并最终引领了参数规模达千亿、万亿的大语言模型时代。

Transformer 概述​

第一步：Token 划分（文本切分）​

Token 是文本的「最小处理单位」，可能是单个字符、单词或子词（如英文中「unhappiness」会切分为「un-happi-ness」）。

第二步：Embedding（向量映射）​

通过 Embedding 层将离散的 Token 转化为连续的高维向量（如 768 维、1024 维），向量是有大小和方向的量，在计算机领域是表示和计算数据特征的重要方式。向量的数值分布隐含语义信息：

语义相近的词，向量距离更近（如「国王」与「女王」的向量距离，远小于「国王」与「汽车」）； 甚至可通过向量运算实现语义推理（如「国王 - 男人 + 女人 ≈ 女王」）。 这一步让模型具备了「理解语义」的基础 —— 机器能通过向量数值的差异，判断词与词之间的关联。

补充知识-点乘​

空间向量有个很重要的计算点乘（Dot Product）

在空间中有两个向量： a⃗=(x1,y1,z1),b⃗=(x2,y2,z2),\vec{a}=(x_1,y_1,z_1),\vec{b}=(x_2,y_2,z_2),a=(x1​,y1​,z1​),b=(x2​,y2​,z2​),    a⃗\vec{a}a与 b⃗\vec{b}b之间夹角为θ\thetaθ 

从代数角度看，点积是对两个向量对应位置上的值相乘再相加的操作，其结果即为点积。

a⃗⋅b⃗=x1x2+y1y2+z1z2\vec{a}\cdot\vec{b}=x_1x_2+y_1y_2+z_1z_2a⋅b=x1​x2​+y1​y2​+z1​z2​

从几何角度看，点积是两个向量的长度与它们夹角余弦的积。

a⃗⋅b⃗=∣a⃗∣∣b⃗∣cos⁡θ\vec{a}\cdot\vec{b}=|\vec{a}| \begin{vmatrix} \vec{b} \end{vmatrix}\cos\thetaa⋅b=∣a∣​b​​cosθ

![450](./assets/LangChain4j Part 1 从对话到行动，ai智能体入门构建/file-20260309130702457.jpg)

几何意义：​

点乘的结果表示  在a⃗\vec{a}a方向上的投影与b⃗\vec{b}b 的乘积，反映了两个向量在方向上的相似度，结果越大越相似。基于结果可以判断这两个向量是否是同一方向，是否正交垂直，具体对应关系为：

  1. a⃗⋅b⃗>0\vec{a} \cdot \vec{b}>0a⋅b>0 则方向基本相同，夹角在0°到90°之间(值越大，两个向量间的关系越大)
  2. a⃗⋅b⃗=0\vec{a} \cdot \vec{b}=0a⋅b=0 则正交，相互垂直
  3. a⃗⋅b⃗<0\vec{a} \cdot \vec{b}<0a⋅b<0 则方向基本相反，夹角在90°到180°之间
第三步：（Multi-head）多头注意力机制​

注意力机制是 Transformer 架构的「灵魂」，本质是让模型学会「聚焦重点」—— 就像人类读文章时会优先关注关键词，模型处理输入时也会为不同部分分配不同权重，权重越高，对当前任务的影响越大。

例如处理句子「我是吉伊，我爱吃零食」时，模型分析「我」一词时，会给「吉伊」分配更高权重，因为它们与「吉伊」的语义关联更紧密。

为应对复杂语义场景，基础注意力机制进一步升级为「多头注意力（Multi-Head Attention）」：

多个「注意力头」同时工作，每个头聚焦不同维度（如 A 头关注句法关系，B 头关注语义关联，C 头关注上下文逻辑）；这里就是并行。 最后将所有头的结果拼接融合，让模型更全面地理解输入信息。

什么是 LangChain4j？​

LangChain /læŋ'tʃeɪn/ 是一个用于开发由大型语言模型（LLMs）驱动的应用程序的框架。它通过模块化组件（如模型、提示、链、代理、记忆、检索等）帮助开发者将大语言模型与外部数据源、工具等连接起来，简化复杂AI应用的构建流程。

目前主流的 Java AI 开发框架有 Spring AI 和 LangChain4j，它们都提供了很多 开箱即用的 API 来帮你调用大模型、实现 AI 开发常用的功能，比如：

  • 对话记忆
  • 结构化输出
  • RAG 知识库
  • 工具调用
  • MCP
  • SSE 流式输出
  • ......

就我个人体验下来，这两个框架的很多概念和用法都是类似的，也都提供了很多插件扩展，都支持和 Spring Boot 项目集成。虽然有一些编码上的区别，但孰好孰坏，使用感受也是因人而异的，LangChain4j 灵活性比较高，经过25年开源社区的沉淀，基本能支撑起企业级小应用。

AI 应用开发​

新建项目​

打开 IDEA 开发工具，新建一个 Spring Boot 项目，Java 版本选择 21（因为 LangChain4j 最低支持 17 版本）： 选择依赖，使用 3.5.0 以上版本的 Spring Boot，引入 Spring MVC 和 Lombok 注解库： 新建项目后，先修改配置文件后缀为 yml，便于后面填写配置。

AI 对话 - ChatModel​

ChatModel 是最基础的概念，负责和 AI 大模型交互。

首先需要引入至少一个 AI 大模型依赖，这里选择国内的阿里云大模型，提供了和 Spring Boot 项目的整合依赖包，比较方便：

<dependency>  
    <groupId>dev.langchain4j</groupId>  
    <artifactId>langchain4j-community-dashscope-spring-boot-starter</artifactId> 
    <version>1.12.1-beta21</version>
</dependency>

需要到 阿里云百炼平台 获取大模型调用 key，注意不要泄露！

langchain4j:

    dashscope:
      chat-model:
        model-name: qwen-max

除了编写配置让 Spring Boot 自动构建 ChatModel 外，也可以通过构造器自己创建 ChatModel 对象。这种方式更灵活，在 LangChain4j 中我们会经常用到这种方式来构造对象。

ChatModel qwenModel = QwenChatModel.builder()
    .apiKey("You API key here")
    .modelName("qwen3.5-max")
    .enableSearch(true)
    .temperature(0.7)
    .maxTokens(4096)
    .stops(List.of("Hello"))
    .build();

有了 ChatModel 后，创建一个 AiCodeHelper 类，引入自动注入的 qwenChatModel，编写简单的对话代码，并利用 Lombok 注解打印输出结果日志：

@Service
@Slf4j
public class AiCodeHelper {
    @Resource
    private ChatModel qwenChatModel;

    public String chat(String message) {
        UserMessage userMessage = UserMessage.from(message);
        ChatResponse chatResponse = qwenChatModel.chat(userMessage);
        AiMessage aiMessage = chatResponse.aiMessage();
        log.info("AI 输出：" + aiMessage.toString());
        return aiMessage.text();
    }
}

编写单元测试，向 AI 打个招呼吧：

@SpringBootTest
class AiCodeHelperTest {
    @Resource
    private AiCodeHelper aiCodeHelper;

    @Test
    void chat() {
        aiCodeHelper.chat("你好");
    }
}

系统提示词 - SystemMessage​

系统提示词是设置 AI 模型行为规则和角色定位的隐藏指令，用户通常不能直接看到。系统 Prompt 相当于给 AI 设定人格和能力边界，也就是告诉 AI "你是谁？你能做什么？"。

根据我们的需求，编写一段系统提示词：

你是编程专家,需要严谨与细致回答用户提出的问题。

想要使用系统提示词，最直接的方法是创建一个系统消息，把它和用户消息一起发送给 AI。

修改 chat 方法，代码如下：

private static final String SYSTEM_MESSAGE = """
    你是编程专家,需要严谨与细致回答用户提出的问题。
    """;

public String chat(String message) {
    SystemMessage systemMessage = SystemMessage.from(SYSTEM_MESSAGE);
    UserMessage userMessage = UserMessage.from(message);
    ChatResponse chatResponse = qwenChatModel.chat(systemMessage, userMessage);
    AiMessage aiMessage = chatResponse.aiMessage();
    log.info("AI 输出：" + aiMessage.toString());
    return aiMessage.text();
}

AI 服务 - AI Service​

在学习更多特性前，我们要了解 LangChain4j 最重要的开发模式 —— AI Service，提供了很多高层抽象的、用起来更方便的 API，把 AI 应用当做服务来开发。

使用 AI Service​

首先引入 langchain4j 依赖：

<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j</artifactId>
</dependency>

然后创建一个编程助手 AI Service 服务，采用声明式开发方法，编写一个对话方法，然后可以直接通过 @SystemMessage 注解定义系统提示词。

public interface AIReportHelperService {
    @SystemMessage("你是编程专家,需要严谨与细致回答用户提出的问题。今天是{{current_date}}")  
String chat(@UserMessage String userMessage);
}

不过由于我们提示词较长，写到注解里很不优雅，所以单独在 resources 目录下新建文件 system-prompt.txt 来存储系统提示词。

@SystemMessage 注解支持从文件中读取系统提示词：

public interface AIReportHelperService {
    @SystemMessage(fromResource = "system-prompt.txt")
    String chat(String userMessage);
}

然后我们需要编写工厂类，用于创建 AI Service：

@Configuration
public class AIReportHelperServiceConfig {
    @Resource
    private ChatModel qwenChatModel;

    @Bean
    public AIReportHelperService aiCodeHelperService() {
        return AiServices.create(AIReportHelperService.class, qwenChatModel);
    }
}

调用 AiServices.create 方法就可以创建出 AI Service 的实现类了，背后的原理是利用 Java 反射机制创建了一个实现接口的代理对象，代理对象负责输入和输出的转换，比如把 String 类型的用户消息参数转为 UserMessage 类型并调用 ChatModel，再将 AI 返回的 AiMessage 类型转换为 String 类型作为返回值。

但我们不用关心这么多，直接写接口和注解来开发就好。你喜欢这种开发方式么？

编写单元测试，调用我们开发的 AI Service：

@SpringBootTest
class AIReportHelperServiceTest {
    @Resource
    private AIReportHelperService aiReportHelperService;

    @Test
    void chat() {
        String result = aiReportHelperService.chat("你好，你是谁，现在是几号");
        System.out.println(result);
    }
}

Debug 运行，发现生成了 AI Service 的代理类，并且系统提示词生效了。是不是比之前自己拼接系统消息要方便多了？

Spring Boot 项目中使用​

如果你觉得手动调用 create 方法来创建 Service 比较麻烦，在 Spring Boot 项目中可以引入依赖：

<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-spring-boot-starter</artifactId>
</dependency>

然后给 AI Service 加上 @AiService 注解，就能自动创建出服务实例了，也就是之前的bean：

@AiService
public interface AiCodeHelperService {
    @SystemMessage(fromResource = "system-prompt.txt")
    String chat(String userMessage);
}

记得注释掉之前工厂类的 @Configuration 注解，否则会出现 Bean 冲突

再次运行单元测试，也是可以正常对话的

这种方式虽然更方便了，但是缺少了自主构建的灵活性（可以自由设置很多参数），所以我建议还是采用自主构建。之后的功能特性，我们也会基于这种 AI Service 开发模式来实现。

会话记忆 - ChatMemory​

会话记忆是指让 AI 能够记住用户之前的对话内容，并保持上下文连贯性，这是实现 AI 应用的核心特性。

怎么实现对话记忆？最传统的方式是自己维护消息列表，不仅要手动添加消息，消息多了还要考虑淘汰、不同用户的消息还要隔离，想想都头疼！

// 自己实现会话记忆
Map<String, List<Message>> conversationHistory = new HashMap<>();

public String chat(String message, String userId) {
    // 获取用户历史记录
    List<Message> history = conversationHistory.getOrDefault(userId, new ArrayList<>());

    // 添加用户新消息
    Message userMessage = new Message("user", message);
    history.add(userMessage);

    // 构建完整历史上下文
    StringBuilder contextBuilder = new StringBuilder();
    for (Message msg : history) {
        contextBuilder.append(msg.getRole()).append(": ").append(msg.getContent()).append("\n");
    }

    // 调用 AI API
    String response = callAiApi(contextBuilder.toString());

    // 保存 AI 回复到历史
    Message aiMessage = new Message("assistant", response);
    history.add(aiMessage);
    conversationHistory.put(userId, history);

    return response;
}

使用会话记忆​

LangChain4j 为我们提供了开箱即用的 MessageWindowChatMemory 会话记忆，最多保存 N 条消息，多余的会自动淘汰。创建会话记忆后，在构造 AI Service 设置 chatMemory：

@Configuration
public class AiCodeHelperServiceFactory {
    @Resource
    private ChatModel qwenChatModel;

    @Bean
    public AiCodeHelperService aiCodeHelperService() {
        // 会话记忆
        ChatMemory chatMemory = MessageWindowChatMemory.withMaxMessages(10);
        AiCodeHelperService aiCodeHelperService = AiServices.builder(AiCodeHelperService.class)
            .chatModel(qwenChatModel)
            .chatMemory(chatMemory)
            .build();
        return aiCodeHelperService;
    }
}

编写单元测试，测试会话记忆是否生效：

@Test
public void QwenAIServiceWithMemoryTest() {  
    String chat = aiReportHelperService.chatWithMemory(1, "你好，我是小明");  
    log.info("{}", chat);  
    chat = aiReportHelperService.chatWithMemory(1, "你好，我是谁");  
    log.info("{}", chat);  
}

进阶用法​

会话记忆默认是存储在内存的，重启后会丢失，可以通过自定义 ChatMemoryStore 接口的实现类，将消息保存到 MySQL ，mongodb等其他数据源中。

/**
 * 基于 MongoDB 的聊天消息存储服务实现类
 * 使用 Spring Data MongoDB 的 MongoTemplate 进行操作
 */
@Resource // Spring 注解，用于按名称注入 MongoTemplate 依赖
private MongoTemplate mongoTemplate; // MongoDB 操作模板

/**
 * 根据记忆ID（会话ID）获取对应的聊天消息列表
 * @param memoryId 记忆/会话的唯一标识
 * @return 反序列化后的 ChatMessage 列表，如果不存在则返回空列表
 */
@Override
public List<ChatMessage> getMessages(Object memoryId) {
    // 1. 构建查询条件：根据 memoryId 精确匹配
    Criteria criteria = Criteria.where("memoryId").is(memoryId);
    Query query = new Query(criteria);

    // 2. 执行查询，返回整个文档对象（包含id、content等字段）
    ChatMessages chatMessages = mongoTemplate.findOne(query, ChatMessages.class);

    // 3. 如果文档存在，则将其中的content字段（JSON字符串）反序列化为消息列表
    if (chatMessages != null){
        String content = chatMessages.getContent();
        return ChatMessageDeserializer.messagesFromJson(content);
    }
    // 4. 文档不存在，返回一个空列表（避免返回null）
    return new LinkedList<>();
}

/**
 * 更新（或插入）指定记忆ID下的消息列表
 * 使用 upsert 操作：存在则更新，不存在则创建新文档
 * @param memoryId 记忆/会话的唯一标识
 * @param list 要保存的 ChatMessage 列表
 */
@Override
public void updateMessages(Object memoryId, List<ChatMessage> list) {
    // 1. 构建查询条件
    Criteria criteria = Criteria.where("memoryId").is(memoryId);
    Query query = new Query(criteria);

    // 2. 构建更新操作：将列表序列化为JSON字符串，并设置到content字段
    Update update = new Update();
    update.set("content", ChatMessageSerializer.messagesToJson(list));

    // 3. 执行 upsert 操作
    mongoTemplate.upsert(query, update, ChatMessages.class);
}

/**
 * 删除指定记忆ID对应的整个消息文档
 * @param memoryId 要删除的记忆/会话标识
 */
@Override
public void deleteMessages(Object memoryId) {
    // 1. 构建查询条件
    Criteria criteria = Criteria.where("memoryId").is(memoryId);
    Query query = new Query(criteria);
    // 2. 执行删除操作
    mongoTemplate.remove(query, ChatMessages.class);
}

如果有多个用户，希望每个用户之间的消息隔离，可以通过给对话方法增加 memoryId 参数和注解，在调用对话时传入 memoryId 即可（类似聊天室的房间号）：

String chat(@MemoryId int memoryId, @UserMessage String userMessage);

构造 AI Service 时，可以通过 chatMemoryProvider 来指定 每个 memoryId 单独创建会话记忆：

    .chatMemoryProvider(memoryId -> MessageWindowChatMemory.withMaxMessages(10))

    .build();

结构化输出​

结构化输出是指将大模型返回的文本输出转换为结构化的数据格式，比如一段 JSON、一个对象、或者是复杂的对象列表。

![](./assets/LangChain4j Part 1 从对话到行动，ai智能体入门构建/file-20260309135736475.jpg)

结构化输出有 3 种实现方式：

  • 利用大模型的 JSON schema
  • 利用 Prompt + JSON Mode
  • 利用 Prompt

默认是 Prompt 模式，也就是在原本的用户提示词下 拼接一段内容 来指定大模型强制输出包含特定字段的 JSON 文本。

你是一个专业的信息提取助手。请从给定文本中提取人员信息，
并严格按照以下 JSON 格式返回结果：

{
    "name": "人员姓名",
    "age": 年龄数字,
    "height": 身高（米），
    "married": true/false,
    "occupation": "职业"
}

重要规则：
1. 只返回 JSON 格式，不要添加任何解释
2. 如果信息不明确，使用 null
3. age 必须是数字，不是字符串
4. married 必须是布尔值

不过我们开发时无需关心这些，只要修改对话方法的返回值，框架就会自动帮我们实现结构化输出，非常爽！

比如我们增加一个 让 AI 总结网络刮刷下来的影片信息的方法，AI 需要输出学习报告对象，包含名称和建议列表：

record Report(String movieTitle, String director, int releaseYear, List<String> mainActors, String genre, String summary){}

工具调用 - Tools​

工具调用（Tool Calling）可以理解为让 AI 大模型 借用外部工具 来完成它自己做不到的事情。

跟人类一样，如果只凭手脚完成不了工作，那么就可以利用工具箱来完成。

工具可以是任何东西，比如网页搜索、对外部 API 的调用、访问外部数据、或执行特定的代码等。

比如用户提问 "帮我查询上海最新的天气"，AI 本身并没有这些知识，它就可以调用 "查询天气工具"，来完成任务。

需要注意的是，工具调用的本质 并不是 AI 服务器自己调用这些工具、也不是把工具的代码发送给 AI 服务器让它执行，它只能提出要求，表示 "我需要执行 XX 工具完成任务"。而真正执行工具的是我们自己的应用程序，执行后再把结果告诉 AI，让它继续工作。

然后在 tools 包下编写工具，通过 @Tool 注解就能声明工具了，注意 要认真编写工具和工具参数的描述，这直接决定了 AI 能否正确地调用工具。

@Component  
@Slf4j  
public class CalculatorTools {  
  
    @Tool(name = "加法运算",value = "计算a和b两个数的相加结果")  
    double sum(double a, double b) {  
        log.info("调用加法运算：a={}, b={}", a, b);  
        return a + b;  
    }  
    @Tool(name="平方根计算",value="计算x的平方根")  
    double squareRoot(double x) {  
        log.info("调用平方根计算：x={}", x);  
        return Math.sqrt(x);  
    }  
  
}

给 AI Service 绑定工具：

// 构造 AI Service
AiCodeHelperService aiCodeHelperService = AiServices.builder(AiCodeHelperService.class)
    .chatModel(qwenChatModel)
    .chatMemory(chatMemory)
    .tools(new CalculatorTools()) // 工具调用
    .build();

检索增强生成 - RAG​

RAG（Retrieval-Augmented Generation，检索增强生成）是一种结合信息检索技术和 AI 内容生成的混合架构，可以解决大模型的知识时效性限制和幻觉问题。

简单来说，RAG 就像给 AI 配了一个 "小抄本"，让 AI 回答问题前先查一查特定的知识库来获取知识，确保回答是基于真实资料而不是凭空想象。很多企业也基于 RAG 搭建了自己的智能客服，可以用自己积累的领域知识回复用户。

护轨 - Guardrail​

其实我感觉护轨这个名字起的不太好，其实我们把它理解为拦截器就好了。分为输入护轨（input guardrails）和输出护轨（output guardrails），可以在请求 AI 前和接收到 AI 的响应后执行一些额外操作，比如调用 AI 前鉴权、调用 AI 后记录日志。

让我们小试一把，在调用 AI 前进行敏感词检测，如果用户提示词包含敏感词，则直接拒绝。

新建 guardrail.SafeInputGuardrail，实现 InputGuardrail 接口：

/**
 * 安全检测输入护轨
 */
public class SafeInputGuardrail implements InputGuardrail {
    private static final Set<String> sensitiveWords = Set.of("kill", "evil");

    /**
     * 检测用户输入是否安全
     */
    @Override
    public InputGuardrailResult validate(UserMessage userMessage) {
        // 获取用户输入并转换为小写以确保大小写不敏感
        String inputText = userMessage.singleText().toLowerCase();
        // 使用正则表达式分割输入文本为单词
        String[] words = inputText.split("\\W+");
        // 遍历所有单词，检查是否存在敏感词
        for (String word : words) {
            if (sensitiveWords.contains(word)) {
                return fatal("Sensitive word detected: " + word);
            }
        }
        return success();
    }
}

LangChain4j 提供了几种快速返回的方法，简单来说，想继续调用 AI 就返回 success、否则就返回 fatal。

修改 AI Service，使用输入护轨：

    }

什么是SSE？​

Server-Sent Events (SSE) 是一种允许服务器向客户端实时推送更新的技术。与WebSocket不同，SSE是基于HTTP协议的，它提供了一种简单的方式来实现服务器到客户端的单向通信。

为什么需要流式输出？​

在AI时代，特别是使用大型语言模型(LLM)构建聊天机器人时，流式输出变得尤为重要：

  1. 用户体验优化：用户可以边生成边看到结果，而不是等待全部内容生成完毕
  2. 响应速度提升：即使内容尚未完全生成，用户也能立即看到部分结果
  3. 成本效益：对于按token计费的AI服务，流式输出可以更合理地分配资源

OpenClaw​

OpenClaw（曾用名Clawdbot/Moltbot）是一款开源的自主AI智能体（Autonomous AI Agent）框架，由奥地利开发者Peter Steinberger于2025年11月创建。它采用MIT协议开源，核心理念是自托管、本地优先，让AI助手运行在用户自己的机器上，对话记录、长期记忆、技能文件全部以纯文本形式保存在本地。

一、定义与核心定位​

OpenClaw是一个统一的大模型API网关，将常用的聊天应用（WhatsApp、Telegram、Discord、iMessage等）连接到AI编程助手（如Claude、GPT等）。其slogan是“The AI that actually does things”，图标设计为“龙虾”。

二、发展历程​

  • 2025年11月：项目创建，最初名为Clawdbot/Clawbot
  • 2026年1月：Clawdbot发布，在GitHub上星标数迅速增长
  • 2026年1月27日：因Anthropic商标问题改名为“Moltbot”
  • 2026年1月30日：最终更名为OpenClaw
  • 2026年2月15日：创始人Peter Steinberger加入OpenAI，OpenClaw以基金会形式作为开源项目存续

三、核心架构​

OpenClaw的架构主要由四个核心组件构成：

组件功能说明
**Gateway（网关）**​核心组件，作为24/7运行的持久化WebSocket RPC服务器，负责连接各类聊天平台、路由消息、管理并发Agent会话、调用LLM API
**Agent（智能体）**​负责驱动思考过程，接入模型以处理上下文记忆与逻辑推理
**Skills（技能）**​功能模块，使其能够执行网页调研、浏览器自动化、访问邮箱等具体操作
**Memory（记忆）**​负责将对话内容与用户偏好以文件形式保存，实现跨会话持久记忆

底层技术基于Pi Agent SDK（又称pi-mono），由另一位奥地利开发者Mario Zechner编写。

四、主要功能特性​

  1. 任务执行能力：通过聊天软件接收指令，直接在本地电脑上执行任务，如整理文件、修复代码、发送邮件、管理日程等
  2. 多平台支持：运行在Mac、Windows、Linux等多种操作系统上，支持接入Anthropic、OpenAI等主流AI模型及本地模型
  3. 持久化记忆：具备强大的记忆功能，能记住用户的偏好、上下文信息和任务细节
  4. 自我进化：用户可教授技能或操作逻辑，OpenClaw能内化为永久技能，在后续任务中应用
  5. 系统操作权限：拥有与人类用户同等级别的系统权限，可直接调用终端、编写脚本、安装软件工具
  6. 多通道集成：支持13+个消息平台，包括WhatsApp、Telegram、Discord、Slack、Signal、iMessage等

系统要求​

  • 操作系统：macOS、Linux、Windows（推荐WSL2）
  • Node.js：版本22或更高
  • 内存：4GB最小（8GB推荐）

六、应用场景​

  1. 个人效率提升：通过聊天软件发送指令管理日程、整理文件、搜索信息
  2. 工作自动化：辅助代码开发、处理邮件、生成项目报告
  3. 家庭自动化：控制智能家居设备、管理家庭购物清单、自动下单
